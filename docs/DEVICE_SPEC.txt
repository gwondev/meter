METER 기술 명세서
주제: AIoT 센서 및 비전 융합 기반 적재량 및 사각지대 통합 수거 관제 플랫폼
갱신: 2026-09-12
서비스: https://meter.gwon.run
저장소: https://github.com/gwondev/meter


────────────────────────────────────────
1. 한눈에
────────────────────────────────────────

  D모듈 (모듈1, m*)
    초음파로 빈 거리 측정 → 보드에서 fillPercent 산출 → MQTT 30초 전송.
    구현 완료 (펌웨어·서버·웹).

  R모듈 (모듈2, r*)
    MQTT로 사진만 전송. 주기는 보드가 자유 결정.
    원본(imageRole=original)은 서버 baseline 덮어쓰기.
    비교 큐 최근 10장 → 서버 vision이 fillPercent 산출.
    큐에서 밀린 사진은 휴지통 약 20장 보관 후 삭제 (관리자 웹에서 관리).
    보드는 판정·수치 계산 안 함 (전송만).

  시리얼 담당
    r1  성권 테스트 R모듈 (프로토콜·서버 검증용)
    r2, r3  수혁 담당 실기기 (r1과 시리얼 겹치면 안 됨)
    m*  D모듈 (높이)

  AI 챗봇
    모듈 DB(적재율·신호) 기반 자연어 질의응답.

  AI 카메라 (웹)
    사진으로 쓰레기 품목 분류(Gemini) → 투입 위치 안내.

  지도
    모듈 위치·적재율·신호. 마커 클릭 시 시리얼·유형·적재율 카드.
    D=초음파 아이콘, R=카메라 아이콘 + 최신 스냅샷.

  최적 수거 경로
    화면 안 모듈 전부 방문. 만재 우선 + 도로망.
    도로가 모듈 앞에서 끊기면 직선 연결, 진행 방향 화살표.

  관리자
    모듈·더미·유저, 무신호 정리, MQTT 진단,
    R 사진 관리(원본 / 비교큐10 / 휴지통20).

  ★공통 지표 fillPercent 0~100
    0 = 수거 불필요, 100 = 즉시 수거.
    D: 보드 계산. R: 서버 vision 계산.

────────────────────────────────────────

────────────────────────────────────────
4. R모듈 — 카메라 이미지 (서버 판정)  = 모듈2
────────────────────────────────────────

  상태     서버·관리자·vision 연동. 보드 프로토콜 확정.
  보드     ESP32-CAM 또는 RPi + 카메라 (프로토콜 동일)
  시리얼
    r1     성권 테스트 (meter_iot/module2, scripts/r1_mqtt_test.py)
    r2,r3  수혁 담당 실기기

  보드
    JPEG만 MQTT 전송. 주기 자유. fillPercent 미전송.
    imageRole=original → 무조건 원본. sample → 무조건 샘플.
    (웹에서 샘플→원본 승격 없음. MQTT role만 진실.)

  서버
    original → baseline.jpg 덮어쓰기, fill%=0
    sample   → samples/ 큐(최대 10) → vision 비교 → fill%
    큐에서 밀림 → trash/ (최대 20) → 초과분 영구삭제
    관리자 웹: 복원·삭제·fill% 재계산만 (원본 승격 UI/API 없음)

  저장
    /backend/uploads/{serial}/baseline.jpg
    /backend/uploads/{serial}/samples/*.jpg   (10)
    /backend/uploads/{serial}/trash/*.jpg     (20)

  보드 테스트 이미지 (r1)
    meter_iot/module2/data/images/*.jpg 넣기 (수십~100장, 장당 ~200KB 이하)
    pio run -t uploadfs && pio run -t upload
    10초마다 순환 전송, 10번마다 1회 original

  테스트 (PC에서 MQTT)
    python scripts/r1_mqtt_test.py --original
    python scripts/r1_mqtt_test.py --count 10

  MQTT 원본
    { "moduleSerial":"r1", "imageRole":"original", "imageBase64":"...", "imageFormat":"jpg" }

  MQTT 샘플
    { "moduleSerial":"r1", "imageRole":"sample", "imageBase64":"...", "imageFormat":"jpg" }

5. 기구 (OpenSCAD) — 기능 출력
────────────────────────────────────────

  파일     meter_HW/r_module_downward_mount.scad
  의도     카메라가 바닥(용기 안)을 내려다보게. D모듈식 림 클립 + 수직 암.
  출력     IT융합대학 무료 출력 → 동방 픽업
  데드라인 2026-10-10 까지 출력본 확보 (기능 기구). 외형 꾸미는 이후 검토.
  참고     첨부 OpenSCAD·D거치 사진이 워크스페이스에 없으면 위 파일로 1차안.
           보드 홀피치·림 두께는 파라미터로 조정.

6. POWER TANK
────────────────────────────────────────

  D·R 상시 전원. 서버 통신 없음.


────────────────────────────────────────
7. 데이터 흐름
────────────────────────────────────────

  D --MQTT fill%-------------------------------┐
                                               ├→ mosquitto → backend → MySQL → 웹
  R --MQTT image (original|sample)-------------┘
        original → baseline
        sample   → samples(10) → trash(20) → vision → fill%

────────────────────────────────────────

  METER_UPLOAD_TRASH_KEEP=20
  METER_VISION_URL=http://meter-vision:8090
